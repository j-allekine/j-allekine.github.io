# Issue tracker: GitHub Issues

Issues and specifications for this repository live in GitHub Issues:

`j-allekine/j-allekine.github.io`

## Conventions

- Keep one feature or independently actionable change per GitHub Issue.
- Use the issue body for the specification, acceptance criteria, implementation decisions, and testing decisions.
- Use GitHub comments for discussion history and follow-up decisions.
- Use the canonical triage labels defined in `docs/agents/triage-labels.md`.
- Apply `ready-for-agent` when a specification is complete and ready for implementation.
- Link blocking and related issues explicitly in the issue body.

## Publishing

When a skill says to publish to the issue tracker, create or update the appropriate GitHub Issue in `j-allekine/j-allekine.github.io`.

When a skill says to fetch a ticket, read the referenced GitHub Issue.

Do not create new local issue or specification files under `.scratch/`.
